# 图文输出约定

report.md 顺序：截至何时知道什么、事件时间线、各方说法与证据、逐条核查、相关法规、声明三层解读、根本问题与条件处理路线、未知及怎样验证、消费者有依据的行动、来源与修订。仅材料分析时开头显著说明。

HTML 用时间线、主张卡片、声明对照和证据关系表达；不要求装饰插画。状态用文字加颜色。事实、说法和推断需写明类别。标题不抢跑，社会影响分析不包装成调查结果。

evidence.json 字段如下，文字均为纯文本。空数组保留，缺口写 unknowns。未涉及声明/法规时保留空数组，不硬凑。

```json
{
  "title": "事件名称与有限结论",
  "as_of": "2026-10-18 18:00 Asia/Shanghai",
  "scope": "地区、年款配置、问题范围、材料限制",
  "summary": "目前支持什么及主要未知",
  "timeline": [{"time": "发生时间或未知", "text": "事件及公开时间", "sources": ["S1"]}],
  "claims": [{"id": "C1", "text": "可验证主张", "status": "有限支持", "analysis": "证据、范围、反证、独立来源数量和判断理由", "sources": ["S1"]}],
  "parties": [{"name": "车主", "text": "说法、证据及未回应事项", "sources": ["S2"]}],
  "laws": [{"name": "规范全名和条款", "text": "法域、效力、适用要件、条件结论及缺口", "sources": ["S3"]}],
  "statements": [{"quote": "必要短摘", "official": "主体、范围、依据、承诺", "social": "公开诉求与分析者问题分开", "language": "字面含义、限定词、推论边界", "sources": ["S1"]}],
  "unknowns": ["未知问题 → 需要什么证据 → 哪里继续查"],
  "sources": [{"id": "S1", "title": "标题", "publisher": "机构/作者", "url": "https://原文地址", "published": "发布时间或未知", "accessed": "访问时间", "origin": "源头与同源关系", "limits": "访问限制、利益关联、适用范围等"}],
  "revision": "v1；更新保留旧版和变化原因"
}
```

原始摘录和支持/反驳关系保存于 report.md 或 JSON 额外字段；页面展示上述摘要。URL 缺失用空字符串，页面显示无可访问原文；未知项写未知，不编造。引用靠近主张，来源表保留原链接。schema仅作渲染输入约定，渲染成功不代表证据已核实。

## v1.1 判断与处理路线

增加可选 `judgments` 数组（安全事件默认填写）：每项为 `name`、`text`、`sources`，渲染器展示单独的“判断与处理路线”区块。内容分别覆盖产品安全目的、失效路径与使用边界、法律义务触发条件、当前应该采取的动作、不同核查结果的分支、改进效果验收。`sources` 引用原账本；`text` 标明是事实、推断、法律条件或建议，不能把应然路线画成已发生时间线。现实走向预测另标“预测”并给依据。

## v1.2 先看懂，再深读

默认 `reader` 为对象：`questions` 数组（每项 `name`、`text`、`sources`）、`routes` 数组（每项 `condition`、`action`）、`next_step` 字符串。头部用 `summary` 给一句有限结论，首屏不堆完整范围声明。三个问题默认：发生什么、问题在哪、应该怎么办；每项先回答，专业词立即用白话解释。路线表明确是建议/条件，不当最新进展。当前证据截止时间必须保留；详细scope、逐条核查、法规、分析和来源保留在“查看完整证据与分析”的展开区。reader缺省兼容旧版。report.md也先写简明说明，再列深读证据，避免同一结论重复多次。用户明确要深度报告时可直接展开。
